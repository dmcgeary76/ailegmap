K-12 AI Legislative Map

An interactive reference for tracking how U.S. states legislate the use of artificial intelligence in K-12 public classrooms.

50 states + territories LegiScan-sourced Relevance-filtered Human-curated

What this is & why

AI is entering K-12 classrooms faster than policy can keep up, and the legislative picture is fragmented across 50 states plus territories — some prohibiting use, some mandating AI literacy, many silent. This project assembles that picture in one place: click a state to see the legislation governing AI in its K-12 public classrooms, color-coded by where each bill sits in the process and by the state's overall regulatory stance.

The goal is a trustworthy, continually-refreshed map — not a dump of every bill that mentions "artificial intelligence," but the ones that genuinely shape classroom practice, vetted by a human before they appear.

Data sources

LegiScan API

Primary source for bill text, status, and history across all 50 states and territories. The sync searches every session (not just the current one), so passed and historical legislation is included.

State education agency guidance

Many states act through department guidance rather than statute. 14 jurisdictions are researched by hand today (backend/data/profiles/); the rest render as "not yet assessed" rather than "no policy". A third, curated layer records notable district, city and county actions — NYC's PK-8 moratorium, Miami-Dade's Gemini rollout, Houston's AI-focused campuses — as the project's on-the-ground sentiment signal.

How relevance is decided

A bill must reference both an AI concept and a K-12 education concept in its text to be considered. Each candidate is scored from its title, then its text is read:

Title saysText saysResult
AI term and education termAI is really in thereHIGH — on the map
AI term and education termno AI in the textLOW, "title only"
Education term onlydense with AI (a heading, or 3+ hits at 1+ per 1,000 words)MEDIUM, "dense" — reviewed first
Education term onlyone definition and nothing elseLOW, "thin mention"
AI only / higher-ed / budget / ceremonial—LOW — held for review

Only HIGH goes on the map without a person looking at it, and every HIGH has in fact been reviewed. Resolutions are listed but never color a state — an adopted "urging the department to…" is not a law. Every include/exclude decision is a row in backend/data/decisions.csv, tracked in git, and survives every future sync.

Status color-coding: Introduced Debated Passed Failed / Vetoed

System architecture

Three curated-or-synced inputs (LegiScan bills, state guidance profiles, local actions) land in SQLite; everything the map shows is derived at read time by FastAPI and rendered on real state geometry.

Using the tool

Run locally

The public map at the root of this site is a static build that reads one exported file; it needs no server. Curation runs locally:

./setup.sh      # venv, npm install, SQLite schema, seed profiles / local actions / decisions
./start.sh      # API on :8000, app on :5173 (with the Review Queue tab)

Sync, score, publish

cd backend && source venv/bin/activate
python -m app.sync.legiscan_sync --all               # LegiScan search + status
python -m app.sync.legiscan_sync --all --score-text  # read new bills' text
python -m app.sync.legiscan_sync --all --rescore     # fold it in, link carry-overs
python -m app.seed                                   # replay decisions.csv
python -m app.export                                 # -> docs/data.json
git add -A && git commit -m "Weekly sync" && git push   # GitHub Action redeploys the map

Full details in the repository README and docs/SYNC_IMPLEMENTATION.md; the data model is in docs/DATA_SCHEMA.md.

2026-09-09 — Text-density scorer, local-actions layer, docs cleanup
  • The text scorer is built and calibrated. --score-text reads each candidate bill's newest text and counts AI-term density. Three runs against 315 real documents taught it Iowa's one-word-per-line "HTML", Missouri's dropped spaces, PDF ligatures and hyphenation. 217 MEDIUM bills became 120; the 45 "dense" ones were reviewed (35 in, 9 out). Utah's Classroom Technology Amendments — passed in March, 55 AI mentions, MEDIUM by title — is the poster child.
  • Local actions: 3 rows → 18 across 10 states under the inclusion rule, each sourced and dated. New York and California are now gray on the legislation layer and red on the local one; Florida is the most permissive state on the ground with no passed law.
  • Static map cache-busts data.json per deploy — viewers were seeing week-old numbers.
  • Removed the PostgreSQL-era setup guides; rewrote the schema and sync docs for the current design; Dockerfiles now build the API and an nginx-served static map.
2026-09-08 — Public map, sync audit, decisions in git
  • The map is public. A static build of the frontend reads docs/data.json instead of the API and deploys to GitHub Pages on every push; this page moved to /about/.
  • Four sync bugs found by reading the results. A full-text NOT (recognizing OR honoring …) clause was hiding statutes (44% of Oklahoma's hits, including its signed Responsible Technology in Schools Act); the title scorer matched "school aid"; re-syncs overwrote real statuses with Unknown; two-year sessions created duplicate rows. All fixed; full re-sync: 2,205 bills across 50 states + DC.
  • Every HIGH bill audited. "Passed into law" went from 8 states (two on a deepfake bill and an arts-commission resolve) to 7 that earned it: CA, ID, IL, MD, OK, UT, VA.
  • Resolutions never color the map. Detected from the bill number or a "Resolve" / "… Resolution" title.
  • decisions.csv holds every include/exclude call; the review UI writes it, seed replays it, so a fresh clone reproduces the curated map. Five more researched state profiles (AR, CO, LA, NM, OK) — 14 of 54.
2026-09-04 — Real state outlines, local actions, MEDIUM no longer auto-includes
  • Actual state geometry (d3-geo Albers USA over us-atlas) with a stacked north-east; a curated local_actions layer with a derived per-state leaning; an audit found 0 of 126 MEDIUM bills had an AI term in the title, so only HIGH auto-includes now.
2026-09-02 — Rebuilt on one data model (v0.2)

2026-07-01 — First full 50-state sync & reliability fixes
  • Full sync: ran the LegiScan sync across all 50 states + 3 territories for the first time — 963 bills found, 194 promoted to the map, 769 held for review. Confirmed LegiScan has no territory coverage at all (GU/PR/VI need the separate manual guidance path).
  • Fixed a truncation crash: some real bill titles exceeded the old VARCHAR(255) limit; widened bill_title to TEXT.
  • Fixed cascading sync failures: one bad insert used to poison the whole run; the sync now rolls back and isolates failures per state.
  • Fixed a "sticky primary" bug: a state's headline bill could never be replaced by a stronger later match. Added confidence/stage tracking so re-syncs promote the best current bill — retroactively fixed CA, TX, RI, and others.
  • Territories: confirmed LegiScan doesn't cover PR/GU/VI at all; re-researched GU (new: an AI Regulatory Task Force + a general GovGuam AI policy, still no K-12-specific answer) and VI (unchanged); added a seed script for PR's guidance and explicit ABSENT records for GU/VI so they show real context instead of empty boxes; drafted outreach emails to both departments.
  • Review queue usability: added an "All states/territories" view and a one-click "Needs review only" toggle. Deliberately skipped adding bill deletion — the sync would just recreate a deleted bill on the next run and erase any prior Exclude decision, so filtering beats removing.
  • Pagination fix: LegiScan's getSearch caps at 50 results per page; six states (CA, NJ, HI, MD, NY, IL) were silently missing bills past page 1 — roughly 144 bills that never reached the review queue. The sync now pages through every result.
